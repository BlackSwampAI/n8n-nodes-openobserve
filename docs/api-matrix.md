# OpenObserve v0.1 API matrix

Research was refreshed on **2026-09-05**. The generated OAS 3.1 contract at [api.openobserve.ai/api-doc/openapi.json](https://api.openobserve.ai/api-doc/openapi.json) is the endpoint/schema source of truth; the [Swagger UI](https://api.openobserve.ai/swagger/) identifies it as `openobserve-api-http` 0.1.0 under AGPL-3.0. Human documentation supplies semantics. The live Cloud contract is not versioned to the pinned OSS release, so every operation is classified below.

Batch 2 live verification against pinned OSS v0.92.2 confirmed all six Stream routes and ordinary JSON ingestion. Stream list returns `{list,total}` with `type`, `keyword`, `offset`, `limit`, and `sort`; its current OAS omits the older documented `fetchSchema`, and list-entry schemas were empty, so Get Schema uses the dedicated endpoint. Create accepts `{fields,settings}` with a `type` query and succeeded for the root test user even though self-hosted UI guidance gates the Add Stream/user-defined-schema UI behind `ZO_ALLOW_USER_DEFINED_SCHEMAS`. Settings accepted a partial `{data_retention:1}` object. Delete Fields accepts `{fields:string[]}` and immediately changed the reported schema. JSON ingestion inferred a stream and returned per-stream `successful`/`failed` counts. The pinned server normalized a hyphen in an inferred stream name to an underscore; ingestion output therefore exposes `requestedStreamName` separately and uses the relevant server status `name` as `streamName` when available. Raw `status` remains intact. Cloud and non-log mutation behavior remain unverified.

Batch 3 verification confirmed SQL Search, Field Values, POST Search Around, ordinary JSON metric ingestion, and all six Prometheus-compatible read routes against pinned OSS v0.92.2. Search uses microseconds; normalized JSON rows support Return All pagination, while raw JSON, CSV, and Markdown are intentionally single-response modes governed by Limit. Both formatted modes were live-verified. Prometheus reads accept RFC3339 times and repeated `match[]`. Standard Prometheus envelopes returned vector/matrix data under `data.result`, while metadata/label/series data used their normal envelope shapes; normalized mode raises an item-aware error for a Prometheus `status:error` envelope while raw mode preserves it. A deliberately empty trace stream made Latest and DAG return HTTP 400 with useful missing-schema/field details; no trace data was seeded because user-facing/manual trace ingestion is out of scope. Latest supports rows-only `from`/`size` pagination; response metadata is not emitted. The current OAS still exposes Service Graph, but current official documentation marks it Enterprise-only and the pinned OSS route returned 404, so it is deferred and not advertised.

Batch 4 verification against pinned OSS v0.92.2 confirmed Function create/list/dependency/update/delete and VRL validation. The node deliberately supports VRL only and fixes the OAS transformation type to `0`; JavaScript transformation mode is not exposed. Function list and dependency responses use `{list:[...]}`; update is same-name only and deletion sends `force=false`. Dashboard create/list/get/update/delete worked in the disposable `default` folder. Create returned HTTP 200 despite the OAS declaring 201. Get returns a versioned wrapper (`version`, `hash`, and the matching `v8` definition); update therefore fetches the current definition, merges only explicitly requested friendly/advanced changes, and sends the complete definition with folder and conflict hash. The current v2 dashboard-folder list returned an empty list on a clean OSS install, so the node includes the implicit Default folder. Panel CRUD remains deferred because its high-entropy panel/tab model and required hash-based concurrency do not yet support a safe, understandable n8n UX.

Status legend: **OAS** means confirmed in the generated contract; **Docs** means also described by current human documentation; **Live** means behavior must still be verified against both the pinned OSS image and Cloud. `{org}` is the organization identifier. Stream type is a query parameter where the contract defines it (`logs`, `metrics`, or `traces`).

## Edition-aware boundaries

The [official comparison](https://openobserve.ai/downloads/) says logs, metrics, traces, dashboards, alerts, and pipelines exist in OSS, while OSS pipelines have limited functionality and Enterprise includes remote destinations. The [Enterprise feature page](https://openobserve.ai/docs/features/enterprise/) identifies advanced security/operations features. [Service Graph](https://openobserve.ai/docs/user-guide/data-exploration/traces/service-graph/) is currently Enterprise-only and is deferred despite its public OAS route. AI/SRE agent, anomaly detection, patterns, service streams, synthetic monitoring, and enterprise RBAC/OpenFGA are explicitly deferred and must not appear without edition gates. The public contract exposing a route does **not** prove OSS availability.

## Trigger feasibility gate

“Alert Triggered” has no inbound-subscription endpoint in the OAS. The feasible design is an n8n webhook plus an OpenObserve alert template/destination referencing it. Before implementation, live tests must prove the exact outbound payload, supported secret header, retries, selected-alert attachment, and safe lifecycle behavior. Automation may delete/update only artifacts it created and marked with a stable ownership identifier; otherwise the node must show setup instructions and require the user to attach a reusable destination manually.

## Research provenance and refresh

- Contract: generated [OAS 3.1 JSON](https://api.openobserve.ai/api-doc/openapi.json), refreshed 2026-09-05 and compared with the public contract exposed by pinned OSS v0.92.2. It reports API document version `0.1.0`, not an OpenObserve product version. No generated client or spec copy is vendored; this avoids importing AGPL material into the MIT package.
- Semantics: current [API index](https://openobserve.ai/docs/reference/api/), [search docs](https://openobserve.ai/docs/reference/api/search/search/), [metric JSON docs](https://openobserve.ai/docs/reference/api/ingestion/metrics/json/), [trace docs](https://openobserve.ai/docs/reference/api/traces/), [function docs](https://openobserve.ai/docs/user-guide/data-processing/functions/), and Dashboard user/API documentation, refreshed 2026-09-05.
- Baseline product: latest non-prerelease GitHub release was [v0.92.2](https://github.com/openobserve/openobserve/releases/tag/v0.92.2), while v1.0.0 release candidates existed. Tests pin v0.92.2 rather than an RC.
- Discrepancy: a path/method diff against the running v0.92.2 OAS found all matrix operations in both contracts. Cloud alone additionally exposed alert SLO-preview and SLO-eligible routes, which are deferred. Schema and behavior differences still require Batch 1 contract tests before implementation.
- Refresh procedure: on every supported-version bump, record the release/tag and image digest, download `/api-doc/openapi.json`, diff only in-scope paths and referenced components, review updated human docs/edition comparison, run the independent OSS and Cloud contract suites, and update this matrix with the access date.

## Ecosystem gate

Searches of OpenObserve’s organization/site, n8n’s integration material, GitHub, and the public npm registry (`npm search openobserve --json`) on 2026-09-04 found no vendor-maintained official OpenObserve n8n action node and no OpenObserve-specific n8n community package. Registry results were SDKs, transports, an MCP server, a CLI, and unrelated framework connectors rather than n8n nodes. Generic HTTP Request and OpenTelemetry paths remain alternatives. This is a discovery result, not a permanent uniqueness claim; repeat exact npm registry and n8n catalog searches before release.
