# OpenObserve v0.1 API matrix

Research was refreshed on **2026-09-04**. The generated OAS 3.1 contract at [api.openobserve.ai/api-doc/openapi.json](https://api.openobserve.ai/api-doc/openapi.json) is the endpoint/schema source of truth; the [Swagger UI](https://api.openobserve.ai/swagger/) identifies it as `openobserve-api-http` 0.1.0 under AGPL-3.0. Human documentation supplies semantics. The live Cloud contract is not versioned to the pinned OSS release, so every operation is classified below.

Status legend: **OAS** means confirmed in the generated contract; **Docs** means also described by current human documentation; **Live** means behavior must still be verified against both the pinned OSS image and Cloud. `{org}` is the organization identifier. Stream type is a query parameter where the contract defines it (`logs`, `metrics`, or `traces`).

## Edition-aware boundaries

The [official comparison](https://openobserve.ai/downloads/) says logs, metrics, traces, dashboards, alerts, and pipelines exist in OSS, while OSS pipelines have limited functionality and Enterprise includes remote destinations. The [Enterprise feature page](https://openobserve.ai/docs/features/enterprise/) identifies advanced security/operations features. AI/SRE agent, anomaly detection, patterns, service streams, synthetic monitoring, and enterprise RBAC/OpenFGA are explicitly deferred and must not appear without edition gates. The public contract exposing a route does **not** prove OSS availability.

## Trigger feasibility gate

“Alert Triggered” has no inbound-subscription endpoint in the OAS. The feasible design is an n8n webhook plus an OpenObserve alert template/destination referencing it. Before implementation, live tests must prove the exact outbound payload, supported secret header, retries, selected-alert attachment, and safe lifecycle behavior. Automation may delete/update only artifacts it created and marked with a stable ownership identifier; otherwise the node must show setup instructions and require the user to attach a reusable destination manually.

## Research provenance and refresh

- Contract: generated [OAS 3.1 JSON](https://api.openobserve.ai/api-doc/openapi.json), accessed 2026-09-04. It reports API document version `0.1.0`, not an OpenObserve product version. No generated client or spec copy is vendored; this avoids importing AGPL material into the MIT package.
- Semantics: current [API index](https://openobserve.ai/docs/reference/api/), [search docs](https://openobserve.ai/docs/reference/api/search/search/), [trace docs](https://openobserve.ai/docs/reference/api/traces/), and user guides above, accessed 2026-09-04.
- Baseline product: latest non-prerelease GitHub release was [v0.92.2](https://github.com/openobserve/openobserve/releases/tag/v0.92.2), while v1.0.0 release candidates existed. Tests pin v0.92.2 rather than an RC.
- Discrepancy: a path/method diff against the running v0.92.2 OAS found all matrix operations in both contracts. Cloud alone additionally exposed alert SLO-preview and SLO-eligible routes, which are deferred. Schema and behavior differences still require Batch 1 contract tests before implementation.
- Refresh procedure: on every supported-version bump, record the release/tag and image digest, download `/api-doc/openapi.json`, diff only in-scope paths and referenced components, review updated human docs/edition comparison, run the independent OSS and Cloud contract suites, and update this matrix with the access date.

## Ecosystem gate

Searches of OpenObserve’s organization/site, n8n’s integration material, GitHub, and the public npm registry (`npm search openobserve --json`) on 2026-09-04 found no vendor-maintained official OpenObserve n8n action node and no OpenObserve-specific n8n community package. Registry results were SDKs, transports, an MCP server, a CLI, and unrelated framework connectors rather than n8n nodes. Generic HTTP Request and OpenTelemetry paths remain alternatives. This is a discovery result, not a permanent uniqueness claim; repeat exact npm registry and n8n catalog searches before release.
