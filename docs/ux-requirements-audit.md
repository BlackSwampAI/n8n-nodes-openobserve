# v0.1 minimum-configuration UX audit

Static minimum-configuration audit completed 2026-09-05 for the 59 advertised action operations and Alert Trigger activation fields, using the generated contracts recorded in [api-matrix.md](api-matrix.md) and existing executor/tests. Pinned OSS v0.92.2 behavior is claimed only where a live suite or explicit probe is recorded in [testing.md](testing.md); this table is not a claim that every valid parameter combination received a new live test. The focused follow-up reverified Alert Get Many/History and Pipeline Get History; Function and Dashboard retain their existing test evidence without new behavioral changes.

`tests/scaffold.test.ts` contains the table-driven 59-operation contract mapping each operation to its minimum user-supplied controls and verifies that every mapped control is visible and marked required. `tests/list-history-defaults.test.ts` separately executes the in-scope Stream, Alert Template, Alert Destination, Alert, and Pipeline Get Many defaults, checks v2 Alert History's filter-free empty wrapper, and proves blank Pipeline History is rejected before transport. Function and Dashboard rely on their existing dedicated tests and were not behaviorally re-audited in this follow-up. Optional filters are intentionally absent from the required-control map; Pipeline History selection is a deliberate product requirement despite the upstream API's optional `pipeline_id`.

| OpenObserve Trigger | Alert Triggered                                                                                      | Folder and selected-alert fields are required. Activation normalizes a non-empty unique alert selection, requires stable workflow identity, and mutates only selected alerts; inbound secret validation precedes workflow output.                                                                                                                                                                                    |

Empty `{}` defaults remain only where they mean “no advanced overrides” and are merged with required friendly fields or a fetched complete object. Optional empty locators/filters are normalized and omitted; malformed locator shapes fail locally with item context. Resource and operation selectors remain expression-disabled, while data fields remain expression-friendly.

The shared error normalizer preserves known HTTP response detail fields (including OpenObserve response data/body), maps the status to a useful n8n error, and redacts credentials, authorization values, URL secrets, and explicitly supplied sensitive destination-header values. It does not copy arbitrary request configuration or telemetry into the displayed error. Runtime behavior can still vary by OpenObserve edition/version; pinned limitations and live evidence remain recorded in [testing.md](testing.md).
